# Phases 3–6 plan: remaining tickets

For the team picking up the rest of the build. Read this to choose a ticket, see what it
depends on, and know what "done" means for it. `docs/PLAN.md` holds the original phase
table; this plan supersedes its Phase 3–6 rows where they disagree, because those rows
predate the code that has since landed. `docs/DESIGN.md` decisions (D-nn) still bind.

State at writing: `main` at `a4e152b`. Phases 0–2 merged, plus 3A (#62), 3B (#63) and
TRA-13 (#58).

## Target end state

Each phase ends when these are observable, not when its tickets are closed.

| Phase | Done when |
|---|---|
| 3 | A trusted local MCP server, a skill, `exec` and `fetch` all work in `bin/travis chat`. Untrusted content from any of them cannot cause an unapproved write: the red-team suite proves it. Tool schemas stay inside the token budget with 3+ MCP servers configured. |
| 4 | MCP servers launch inside the OS sandbox on Linux, macOS and Windows. The same escape test passes natively on all three. The status bar reports the real tier, and `require_sandbox` refuses to start below it. |
| 5 | Travis speaks short `<speak>`-tagged updates and spoken approval alerts. Push-to-talk dictates into the input box. Approvals stay keyboard-only (D-10). Voice is off by default and degrades with a clear message where unsupported. |
| 6 | `docs/EVAL.md` is regenerated by one command from live runs: pass@1 with 95% intervals, pass^k, cost, latency, attack success rate with defences on and off, and the ablation table. Replay regression runs on every PR. |

## Ticket rule

One ticket per lettered sub-phase (3C, 4A, …), one owner, normally one PR. The phase files
list each ticket's checklist in commit order. A ticket splits into -a/-b (as 2C did) only
when it outgrows one review or two people want to work its halves in parallel.

## Temporary states

States that exist on `main` today or will exist mid-plan. Each has a ticket that ends it;
none should survive as permanent design.

| Temporary state | Risk while it lasts | Ended by |
|---|---|---|
| Untrusted content is delimited but never marks the next step, so policy does not ask | Injected text can trigger unapproved writes | 3F |
| MCP servers inherit travis's full environment, including the provider key | Third-party code reads secrets | 3F |
| `skills.load_workspace` flag gates workspace skills | Users either never see them or trust them blindly | 3F (flag deleted, approval modal instead) |
| `/tools` reads a list captured at startup; `Registry.Prune` keeps the first N | MCP tools that connect later are invisible or cut arbitrarily | 3C (`ToolNames` field deleted) |
| MCP servers run unsandboxed; tier reported as `none` | Trusted-only use is the only safe use | 4E |
| Voice output ships before voice input | None; input is additive | 5C |

## Permanent limitations (documented, not temporary)

- Windows sandbox has no network containment without admin rights (D-12). The UI says so.
- macOS `sandbox-exec` is deprecated by Apple but still the only unprivileged option.
- Eval sample sizes support only large differences; `docs/EVAL.md` states the intervals.

## Verification

- Static, every ticket: `make check` (lint, vet for all three GOOS, tests, govulncheck).
- Runtime, every ticket: drive `bin/travis chat` (via `make chat` once TRA-37 lands) in a
  tmux pane. No TUI control skill exists in this repo; golden-frame tests cover rendering.
- Every ticket from Wave 1 on adds at least one 6A scenario. Tickets that touch untrusted
  input add a red-team case.
- Phase gate: scenario suite and red-team suite green at the end of Phases 3 and 4.
- macOS: PRs for 4C and 4E carry the `ci:macos` label.

## Implementation guidance

- Run the `how` skill over an unfamiliar subsystem before changing it: the broker wire
  protocol (3D, 3E, 4A), `internal/tools/mcp/supervise.go` (3F, 4E).
- Run `architect` before the three new seams: `sandbox.Spec`, the `Speaker` port, the
  eval results schema.
- Run `interrogate` on 3F's untrusted marking and the 4B–4D escape test before merge.
- Before each commit: manual diff review, `no-comments`, `unslop` on PR text.
- After opening a PR: the Babysit playbook.
